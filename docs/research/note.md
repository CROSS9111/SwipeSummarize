# 技術記事執筆インストラクション

## 概要

このインストラクションは、note / Zenn / Qiita などに投稿する技術記事を執筆する際のフレームワークです。
特に「**再現性が高く、初学者にも伝わる技術記事**」を書くことを目的としています。

---

## 記事の基本構成

### 1. タイトル

- **共感を呼ぶフレーズ**を入れる（例：「[今更]」「つまずいた」「やってみた」）
- 何をする記事なのかが一目で分かるようにする
  （例：「Claude Desktop に MCP を導入する」）
- 検索されやすいキーワードを含める

### 2. はじめに（リード文）

- **読者の状況に共感**する
  （例：「同じところで詰まった方も多いのではないでしょうか」）
- この記事で何が得られるかを 1〜2 文で説明
- 実体験ベースであることを示す
  （例：「実際に自分が躓いたポイントも含めて解説します」）

### 3. 前提知識・背景説明

- 専門用語は簡潔に説明する（深入りしすぎない）
- 「〜とは？」セクションは **3〜5 行程度**に収める
- 箇条書きで要点を整理する

### 4. 前提条件

- 必要な環境・ツールを箇条書きで明示
- バージョン指定がある場合は必ず記載
- OS 差異がある場合は注記する

### 5. 手順（メインコンテンツ）

- **Step 1, Step 2...** と番号付きで進行
- 各ステップは「1 アクション」に絞る
- コマンドは **コピペ可能な形式**で記載
- 補足説明や注意点は本文から切り離して記載する

### 6. 動作確認

- 成功した場合の状態を具体的に記載
- 試せるサンプルコマンドや操作例を提示

### 7. トラブルシューティング

- よくあるエラーと解決策をセットで記載
- ログの確認方法を明示
- 「〜の場合」という条件分岐形式で整理

### 8. 注意点（該当する場合）

- セキュリティ上の注意
- 運用上の注意
- 料金・制限・クォータに関する注意

### 9. まとめ

- 所要時間の目安を記載
- **重要ポイントを 3 つ程度**に絞って箇条書き
- 前向きな締めで終える
  （例：「同じところで詰まった方の参考になれば幸いです」）

### 10. 参考リンク

- 公式ドキュメント
- 参考にした記事
- 関連リポジトリ

---

## 文体・トーンのルール

### 基本姿勢

- **フレンドリーだが馴れ馴れしくしない**
- 「です・ます」調で統一
- 読者を見下す表現をしない

### 避けるべき表現

- ❌「簡単です」「すぐできます」（感じ方に個人差があるため）
- ❌ 専門用語の羅列（必ず補足説明を入れる）
- ❌ 曖昧な指示
  （例：「適宜設定してください」→ 具体例を示す）

### 推奨する表現

- ✅「〜の場合は」で条件分岐を明示
- ✅「ポイント：」「注意：」で重要情報を強調
- ✅ 実際に遭遇したエラーメッセージを引用

## 表・構造化表現に関するルール（note 対応）

### 表形式について

- Markdown の表形式（`| 項目 | 値 |`）は使用しない
- Mermaid 記法（graph / sequence / flowchart 等）は使用しない

### 表の代替表現

表で整理したい内容は、以下の形式で記述すること。

#### データセット

- **項目 1:** 値 1
- **項目 2:** 値 2
- **項目 3:** 値 3

#### 分析結果

- **指標 A:** 結果 A
- **指標 B:** 結果 B
- **指標 C:** 結果 C

### 構造・関係性の表現（Mermaid 代替）

構成・依存関係・階層構造を説明する場合は、
以下の **記号ツリー形式** を使用する。

記法ルール：

- 階層はインデントで表現する
- 使用記号は「├」「└」「│」を用いる
- 箇条書き（- や \*）と混在させない

記述例：

```
Webアプリケーション
　├ フロントエンド（Next.js）
　│　├ ページコンポーネント
　│　├ 共通UIコンポーネント
　│　└ API呼び出しロジック
　├ バックエンド（API）
　│　└ 認証・ビジネスロジック
　│　　　└ データアクセス層
　└ インフラ
　　　└ クラウド環境（AWS）
```

※ 見た瞬間に構造が理解できることを最優先とする
※ 必要に応じて、直前に 1 行の説明文を入れる

## パス表記ルール

- 絶対パスを推奨
- ユーザー依存部分は `あなたのユーザー名` などで明示
- OS 差異がある場合は併記する

- [ ] 専門用語に説明があるか

- [ ] 参考リンクは有効か

## 使用例

**プロンプト例：**

```
「Docker Composeで Next.js の開発環境を構築する」
という技術記事を書いてください。
実際に自分で試して動作確認済みの内容として書いてください。
```

**期待される出力：**
上記の構成・ルールに沿った、
再現性が高く、初心者にも理解できる技術記事
